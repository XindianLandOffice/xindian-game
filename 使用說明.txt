《動物街救援隊：怪盜的假拍賣》GitHub Pages 版 v2
=================================================

一、要上傳到 GitHub 的檔案
------------------------
請將以下檔案放在現有 GitHub Pages 網站的同一個資料夾（通常是 repo 根目錄）：

  index.html      首頁、正式競賽、試玩、挑戰、後台介面
  style.css       適配 iPad 的版面、卡牌翻牌動畫
  game.js         遊戲玩法與計分
  cloud.js        透過 GitHub Contents API 讀寫 JSON
  setting.json    全部遊戲設定、卡池、劇情文字與媒體路徑
  record.json     四組成績及個人挑戰排行榜

不要只上傳 index.html：它需要讀取其餘檔案。
如果使用自訂網域，進後台「GitHub 同步」輸入 Owner、Repo、Branch；一般 username.github.io/repo/ 網址會嘗試自動判斷。

二、iPad 頁面適配
------------------------
建議使用 2018 iPad（第 6 代）橫向操作。
版面依可見視窗高度自動壓縮，減少 Safari 上方網址列佔用造成的捲動。
若想最大化畫面，可在 Safari 開啟遊戲網址 → 分享 →「加入主畫面」，再從主畫面啟動。網頁不能自行強迫 Safari 隱藏工具列。

三、三種遊玩模式
------------------------
1. 正式競賽：首頁選 A–D 組；五人輪流計時，每人 1–4 次取最佳，接著每人抽卡若干次。計時與抽卡各 50 分，合計 100 分。
2. 試玩：首頁「試玩」，計時一次、抽卡一次，不進入正式四組成績，也不寫 record.json。
3. 挑戰：首頁「挑戰」，輸入暱稱，可單獨玩計時（一次）或翻牌（五次累加），分開顯示排行榜。成績先存在本機，有授權時寫入 record.json。排行榜同一暱稱只顯示最佳成績。

當第一階段「每位學生嘗試次數」設為 1 時，五人仍各可得滿分 10 分，總共最高 50 分；第二階段「每人抽牌次數」設為 1 時，系統自動將全隊抽牌原始點數 ×2，使最高分也能達到 50 分。設為 2 時按原始分數計算；其他回合數按比例換算到 50 分。

計時誤差在 5.00 秒以內（含 5.00）至少有 1 分，超過 5 秒才為 0 分；越接近指定秒數，分數越高。前 3 秒顯示與否可在後台調整。
每位玩家更換時會短暫跳出提示；翻牌後三張一併公開，選中的卡牌有醒目樣式與翻面動畫。

四、手機修改 setting.json（重要）
------------------------
GitHub Pages 是靜態網站：任何人都能讀公開的 setting.json，但沒有 GitHub 身分授權就不能修改倉庫內的 JSON。

正確操作：
1. 在手機開啟同一個 GitHub Pages 網址，按「設定」，輸入 PIN（預設 2468）。
2. 點「GitHub 同步」，確認 Owner、Repo、Branch。
3. 到 GitHub 網站建立 Fine-grained Personal Access Token，只允許這一個儲存庫，權限「Contents: Read and write」。
4. 將 Token 貼入後台，按「使用此 Token」。Token 只存在目前分頁的 sessionStorage，不會寫入 setting.json、record.json 或前端程式碼。
5. 調整遊戲設定、卡牌、計分、盲選及劇情後，點「儲存設定」，網頁就會透過 GitHub API 更新 setting.json。
6. iPad 下次載入或下一組開始時會讀取最新版設定。若 GitHub Pages 快取尚未更新，開始新組時也會嘗試讀取 GitHub API 的最新版本。

PIN 只是避免學生誤觸後台，不能當作真正的網路安全驗證！因為純前端網頁無法安全地把秘密藏在網站程式內。真正的寫入權限來自 GitHub Token。請勿把 Token 直接填進任何 JS 或 JSON，也不要使用可存取所有儲存庫的高權限 Token。

在手機後台更新劇情圖片/GIF：先於「GitHub 同步」設定 Token，再到「劇情圖片」上傳（建議檔案小於 1.5 MB），會自動上傳到 repo 的 assets/ 路徑。然後點「儲存設定」發布圖片連結。上傳大圖、長 GIF 會增加 2018 iPad 的負擔。

五、record.json 的自動寫入：必讀
------------------------
純 GitHub Pages 網頁無法在沒有任何憑證的情況下，自動將學生的分數寫回 GitHub。

想要自動同步，工作人員需在「執行正式競賽的 iPad」同樣進設定 → GitHub 同步，輸入具備該 repo Contents: Read and write 權限的 Token。此動作只需在該分頁的工作階段設定一次；若關掉分頁，可能需要重新輸入。

之後每組完成或個人挑戰結束：
- 先儲存到 iPad 的本機瀏覽器（localStorage）。
- 有 Token 時自動以 GitHub API 更新 record.json。
- 沒 Token / 網路不穩時留在本機待同步清單；可在設定 → GitHub 同步按「同步待上傳成績」。
- 正式結局頁也會提示是否還有待上傳成績。

換裝置不會自動讀到另一台裝置「尚未同步」的本機成績，因此無法完全避免裝置遺失或清除瀏覽器資料的風險。活動前請確認 iPad Token、網路及成功同步，活動中定期下載成績備份。若不能接受任何 Token 在共用 iPad 上出現，則需另外使用後端／Serverless 服務，不能只靠靜態 HTML、JS 和 JSON。

record.json 範例結構：
{
  "version": 2,
  "updatedAt": null,
  "teams": { "A": {"timing": 40,"cards": 35,"total": 75,"completedAt": "..."} },
  "challenges": [{"id":"...","stage":"timer","name":"小水豚","score":9,"at":"..."}]
}

六、修改後台、注意事項
------------------------
計分 / 嘗試次數 / 抽卡數量 / 獎勵門檻 / 盲選 / 卡背提示 / 封面 / 過場 / 結局等，可在後台修改；設定只對下一個新開始的小組生效，進行中的小組沿用開始時的設定。
後台 PIN 可在「GitHub 同步」變更；更改後仍需發布 setting.json 才會對其他裝置生效。
四組可選擇相同牌序（公平比較），挑戰模式會每次重新洗牌，避免玩家記住卡片位置。
請使用暱稱參加自由挑戰，不要蒐集孩子的真實姓名、電話或個資；公開 repo 的 record.json 及排行榜也是公開資料。

七、離線試玩
------------------------
解壓縮後直接打開 index.html 可能因瀏覽器的 file:// 限制而無法讀取 setting.json；正式請使用 GitHub Pages 或其他靜態網站服務。如只想單檔點開體驗，可使用另附的「單檔快速試玩.html」，但單檔試玩不支援 GitHub JSON 同步。

八、驗證狀態
------------------------
已使用 Chromium 模擬 1024×630 可視畫面檢查：開場、正式 10 次計時、抽卡 10 次、三牌揭曉、過場、結局；並驗證試玩、個人挑戰、單次回合換算、±5 秒保底分及後台進入流程。
GitHub JSON API 的讀寫合併邏輯已用模擬 API 測試；尚未實際在你的 GitHub Repo 寫入或在實體 2018 iPad 上操作。正式活動前需以實機、真實 Repo、網路及 Token 完整驗收。
